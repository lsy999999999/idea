# 首轮探索任务

用户希望先做出一个真正能发现新的、值得继续的 idea 的 agent 体系。请利用知识广度和协作，寻找已有解释遗漏的区分，形成可操作的新概念、变量、关系或函数，并实际取证。科学问题及答案没有预先固定。

## 可用线索

1. `bootstrap/scout/candidates.json` 和 `SCOUT_REPORT.md`：独立 Luna 侦察了公开河温与太阳观测的可得性。河流数据优先级来自能立即取得真实测量，不是已证明的新颖性。可以拒绝、修改或离开这两个题目。报告中的样本覆盖仍需核查，尤其请求时间跨度和返回观测条数是否一致。
2. `bootstrap/design_recommendations.json`：另一 Luna 提出了软件验证及服务系统方向，尚需检验相关工作。合成或软件实验应说明环境范围。
3. `docs/DISCOVERY_PROTOCOL.md`：可用工作原则。该协议支持探索，不要求先建完整benchmark。

项目根目录：`/Applications/ideas/1103_boundary_discovery`。
数值环境：项目 `.venv/bin/python`，含 numpy、scipy、pandas、scikit-learn、requests、beautifulsoup4。
公开资料可用 curl、urllib 或 requests 获取。Google 和 OpenAI 文档站访问不稳定，但侦察已访问 USGS、NOAA 和 OpenAlex。遇到取数错误，应检查状态码、响应内容、覆盖范围和时间戳。

## 本轮要交付什么

- 一个由可检查观察或知识冲突支撑的问题。资料暂不支持时，改进问题或另选问题。
- 至少一个具体候选解释；说明相对最接近的已知工作，它希望增加的内容。
- 一次实际执行、能改变我们对候选判断的分析或实验，连同原始材料、代码和输出。
- 根据结果明确保留、修订或放弃什么，以及下一项最有价值的验证。

新颖性检索应帮助形成更好的问题，不要因为邻近领域已经有一般性“记忆/滞后/状态”概念就提前终止所有探索。与此同时，不把已知滞后特征的常规预测改善称为新机制。若没有得到新发现，就留下可复现的失败、具体改进和仍值得检验的候选。

优先真实观察和可以追加的证据。若转向软件/模拟，应研究可独立复现的行为或提出新方法，不要由组织者把正确机制藏起来再声称科学发现。

资源上限：首轮最多 7 次研究角色行动，协调调用另计；每次默认 15 分钟。单个下载尽量小于 100 MB，总数据尽量小于 500 MB，单次数值计算尽量少于 3 分钟。先用本机 CPU。无需启动服务器、发表、推送或联系外部人员。

最终用中文给出研究报告和简明候选卡，引用本次真实文件与检索来源。
