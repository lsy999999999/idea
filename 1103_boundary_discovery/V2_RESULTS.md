## 实际改了什么

- 两个研究者从同一初测出发，在不同上下文独立提出解释；随后跨域角色查阅真实资料，识别已有知识及候选之间是否真的不同。
- 解释拥有不可覆盖的 ID、测量定义、预测、修订来源及证据状态。修订来源与逻辑依赖分别记录；旧解释失败不会自动否定一个为替代它而提出的新解释。
- 计划者每轮比较至少两个实验。选定计划先保存预测、分类规则、影响映射与哈希，再交给实验者执行。
- 结果按预定映射更新账本。执行失败不构成科学反证；相互矛盾或不确定的证据保留。独立复核者重算结果，最后报告必须覆盖全部解释和实验。
- 首次真实调用因连接中断超时，新增的一次有界重试恢复了运行。实验失败不自动重跑，以免隐藏重复试验。

## 首轮发现了一个方法问题

首轮从 SQLite 的 checkpoint 调度问题出发。第一项策略实验没有得到明确结果，并暴露了计划中留出轨迹数量不一致的问题。之后，计划者把两个实验槽用于读者年龄与快照位置检验：12 组年龄对照没有帧数差异；12 组位置扫描得到一致的 2/14/25 帧顺序。

这些测量真实且可复算，但位置效应主要重现官方文档已经解释的机制。**会选便宜、可区分的实验，不等于会选能推进原问题的实验。** 容易验证的已知事实挤掉了尚未解决的策略问题。

另一个细节是证据适用范围：固定快照位置的年龄实验，可以否定本地年龄惩罚预测，却不能直接验证“改变快照位置会改变结果”。账本的支持状态仍需按实际测试的预测解释，不能视为整项理论成立。

## 已执行的进一步修正

新增 `selection_guard.py`。每个计划须说明它如何推进固定研究目标、已有工作解释到哪里、结果会改变哪个决定，以及是否已有执行条件。有可执行的目标实验时，校准不能取代它；选择校准必须指明它解除哪个目标实验的具体障碍。

从第一项策略实验后的证据快照建立继续运行，保留原三轮产物。新的计划者选择了两个未测轨迹形状上的策略比较，修正了完成量指标，并把成本区间跨零归为不确定。这次没有继续做已知机制检验。

这是一次针对失败原因的修订运行；既有结果被继承，研究目标被显式固定。因此，它展示了选择行为变化，不能用来估计方法的平均发现率或因果性能增益。

## 追加实验得到什么

比较固定周期、WAL 增长触发、利用当前读者生命周期的三种策略。最终保存的 72 次数据库运行覆盖两个轨迹形状，各有 12 个随机策略执行顺序；每次提交 240 行，最终数据内容一致，残余帧为零。

下表是“生命周期策略减去基线”的累计 checkpoint 时间差，单位毫秒。负值表示候选更快；区间来自按执行顺序种子配对的 bootstrap。

| 轨迹 | 相对固定周期 | 相对 WAL 增长触发 |
|---|---:|---:|
| H2 | −0.080，95% 区间 [−0.117, −0.050] | −0.021，[−0.070, +0.017] |
| H3 | −0.047，[−0.176, +0.085] | +0.155，[+0.050, +0.269] |

候选在 H2 比固定周期快，但 H3 比 WAL 增长基线慢；预定的读写延迟条件也没有全部满足。最终分类为 `uncertain_or_tradeoff`，没有稳定的总体收益。区间跨零不能证明效果为零；延迟区间上界大于零也不自动证明延迟显著恶化。

这说明单靠减少回收调用数或观察读者释放，还不足以在这些轨迹中保证性能改善。后续值得问的是：**什么可观测条件能区分“释放后立刻回收有利”与“继续积累工作更有利”？** 这仍是候选研究问题，未建立新的机制或算法。

## 结果的实际范围

这些是单个 SQLite build 上的小型、串行、本地回放。随机种子主要改变策略执行顺序，没有生成独立的生产工作负载。微小的 API 时间差不等于实际系统吞吐、服务延迟或部署收益；研究角色的成本也不包含在表中。

追加实验的事件日志记录了两次完整脚本执行：第一次不确定性计算用了与计划不同的随机种子，实验者修正为 3104 后重跑。最终文件保存第二组 72 次测量，第一次汇总仍在工具日志，但其原始逐次数据没有单独保留。两次均报告不确定/权衡，不能当作两个独立确认。见 [重跑来源记录](runs/v2_sqlite_goal_guard_002/contributions/001_execution_provenance.json)。

## 如何继续提升发现性能

优先保持三个约束：实验要推进未决研究目标；结果只更新它实际检验的预测；计划中的工作负载、样本数量与判定条件必须相互一致。目标约束已经接入并真实运行；后两项目前结合结构检查与研究者复核，尚不能由程序完全保证。

随后应在多个独立探索任务上，用相同模型、工具与预算比较强单 agent 和本体系，测量有用新判断的产出、取得区分性证据的成本及需要主控救场的次数。本次没有执行该对照，因此不把更多角色、更多实验或成功结束当作性能提升证据。
