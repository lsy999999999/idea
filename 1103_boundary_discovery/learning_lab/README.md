# 持续学习与共同提问实践

执行依据为用户批准的 `PLAN_SOURCE.md`。首轮使用两个科学情境：微生物群落恢复 × 非平衡物理、免疫记忆 × 非平衡物理。同一物理研究者跨任务保留身份和知识，生态学与免疫学研究者分别保留自己的长期笔记。

## 运行

在项目目录执行：

```bash
.venv/bin/python -u src/learning_lab.py --case both
```

使用已登录的 Codex CLI，请求模型 `gpt-6-luna`、推理强度 `low`。首轮材料准备最初使用 `medium`，后续调整记录在运行目录的控制器修订文件中。每次研究角色调用上限 420 秒，材料准备和最终检查上限 600 秒。每个情境最多 12 个逻辑调用，共 24 个；只有交流提出实际学习缺口时才调用补学。超时阶段最多增加一次恢复调用，复用已有材料，缩小为必需输出。中断后使用相同参数恢复，成功阶段按哈希复用；原始超时记录保留。

这是一轮有预算的小型研究过程。先独立形成理解，再按先后次序交流；补学内容由交流产生，两位研究者带着新知识重新回应。阶段顺序用于本轮观察，不作为所有研究的固定轮次。后续可沿保存的问题继续。

首轮 CLI 出现限流后，通过原生子代理接续。运行 `.venv/bin/python src/learning_lab.py --case both --executor queue` 会保存下一个角色的 `PENDING_NATIVE.json` 后以状态码 75 退出，这是等待派发而非研究失败。主控按其中的任务、输入和工作区派发指定模型，完成后使用 `.venv/bin/python src/import_learning_handoff.py --run <运行目录> --agent <实际代理名>` 校验并接纳，再执行相同 queue 命令推进。完整变化见 [EXECUTION_ADAPTER_CHANGE.md](EXECUTION_ADAPTER_CHANGE.md)。

## 保存与取回

- `library/`：按内容哈希保存初始公共资料，任务中的 `source_catalog.json` 记录原 URL、可读范围与原始路径。补学资料保存在对应阶段工作目录，长期笔记可追溯到该阶段。
- `researchers/<身份>/identity.json`：稳定身份和主要范围。
- `researchers/<身份>/notes/<概念>/vNNN.json`：概念、条件、使用例子、疑问、来源、知识类型、来源任务和修订原因。
- `researchers/<身份>/index.json`：指向当前版本；旧版本保留，修订必须说明原因。
- `runs/learn_20261104_<情境>/memory_retrieval/`：每次实际提供给研究者的不可变记忆快照。词项重合排序，每次最多取回四条完整笔记，同时提供当前知识索引。
- 同一运行目录的 `stages/`：完整提示、实际工具调用、原始来源、讨论、补学、分支和模型输出。
- `ideas.json` 与 `check_report.json`：全部候选，以及相近已有方向、明显数学/逻辑错误两个独立结论。
- `research_experience.json`：把候选和两项检查结论一起写回研究者长期记忆，保留来源任务，避免把旧猜想当作独立发现。
- `08_fresh_continuation`：新调用只用取回的笔记与简短情境继续提问，展示跨调用接续。

知识类型区分来源知识、研究者理解、假说和纠正；熟悉程度区分阅读、解释和实际使用。该标签是带例子与出处的自述，报告会检查实际内容。共享资料不强制统一观点。

并发控制器使用文件锁；角色只写自己工作区，主控串行提交长期记忆。检索校验当前版本哈希，提交校验来源结果哈希；同一阶段重复提交不重复生成版本。

## 本轮查看什么

观察初始问题怎样变化、哪次交流触发何种学习、补学是否改变理解、后续任务具体用了哪条旧知识。查重比较核心方向，相近就标已有；不要求候选当场得到解决、证明或实验验证。运行测试用于检查这套过程，不视为方法优于对照或科学新颖性的证明。

实现验证：`.venv/bin/python -m unittest discover -s tests -p 'test_learning_*.py' -v`。当前 11 项通过；结果存于 `TEST_RESULT.json`。`src/audit_learning_lab.py` 检查实际角色产物、工作区及取回笔记的来源哈希，生成 `AUDIT.json`。
