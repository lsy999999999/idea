# 受限数据来源下的协作提问：首轮结果

现有持续记忆、学习流程和历史结果均未改动。新增入口已用 **GPT-6 Luna / low** 完成一次物理主导的协作试跑，保留了一个候选问题。**没有确认新研究方向；其形成过程中出现了一个被双方接受并写入记忆的坐标错误，最终完整推理复核发现了它。**

## 实际搭建了什么

新增代码位于本目录。`run.py` 导入原来的 `Memory` 类，另建受限任务分支，保存个人笔记、共享问题版本、实际记忆取回包和全部候选。两位研究者均先独立理解，再回应、提出补学请求和返回讨论；不设固定提案者与反驳者。

`isolated_cli.py` 关闭搜索、浏览器、shell、插件、自动记忆和执行 host，忽略项目指导，使用空临时工作目录；研究材料全部作为明确输入传入。每次保存 CLI 事件，出现外部工具执行就不接纳输出。执行 host 被关闭的启动通知保留在原日志里，没有当成一次研究工具调用。

原系统 312 个文件的哈希在运行前保存，运行后复核均未变化。原持续记忆的 11 项测试通过；新增来源和语法边界的 7 项测试通过。测试只说明记录与边界机制工作，不说明研究能力或新颖性。

## 材料是否符合限制

使用 UCI 翼型风洞噪声数据，1,503 行、106 个工况频谱。研究者拿到原始数据、字段和测量条件，没有拿到来源报告 *Airfoil self-noise and prediction* 的正文、摘要、作者解释或后续论文。来源报告的索引日期为 1989-07-01；补充材料保守限于 **1988-01-01 之前**。

允许材料为四份早期索引摘要/摘录：Buckingham 1914、Lighthill 1952、Curle 1955、Welch 1967。没有把摘要说成读过全文。当前仓库元数据与含现代论文的检索结果只在主控侧用于来源核对，没有进入研究输入。

NASA 页面和 API 返回 403，报告最早公开版本尚未独立确认，不能宣称精确重建了它发表前的知识状态。研究模型的预训练知识也未被清除。因此这是限制实际供应和检索材料的试跑，不是严格无泄漏的历史再发现。

旧长期笔记的日期与依赖链不足以满足本次限制，23 个历史版本均未提供。原库保留；本次使用相同记忆实现继续写入独立分支。这次证明的是本任务内的持久接续，没有新证明跨任务知识迁移。

## 一个问题怎样变了

| 阶段 | 实际问题或变化 |
|---|---|
| 声学研究者独立理解 | 用频率 × 弦长 ÷ 流速，即 `fc/U`，能否更一致地对齐不同工况的谱峰？ |
| 物理研究者独立理解 | 用流动时间尺度归一化后是否有稳定谱形？怎样区分重复性与工况相似性？ |
| 相互回应 | 位移厚度/弦长是否应加入比较？能否找到足以区分两种尺度的配对工况？ |
| 交流触发补学 | 物理研究者请求完整 CSV，检查配对覆盖。主控实际提供了全部数值。声学研究者没有提出需要立即执行的补学。 |
| 返回讨论 | 问题转向完整谱形、工况耦合，以及厚度比的额外作用是否可辨识。 |
| 新会话接续 | 从本次已存笔记取回两个具体版本，继续问“哪些匹配比较能检验谱形可比性”。未重新交付全部对话。 |

初始问题已有明显重合。第二位在交流时把“此前的问题”表述为第一位围绕厚度比提出的问题，而没有清楚追踪自己最初关于稳定谱形与重复性的疑问。两段文字并非逐字相同，这是控制器依据原文作出的归属疑点判断。原文和个人问题轨迹保存在 `run/question_attribution_audit.json`；不能把这一自述当成两个独立问题真正合成了第三个问题的充分证据。

## 保留的候选

**候选尺度与跨工况谱形比较**：检验完整谱形按 `fc/U` 重排是否更可比较，以及现有工况能否区分位移厚度/弦长的额外作用。

原始候选、动机及出现路径保存在 [ideas.json](cases/airfoil_001/run/ideas.json)。另保留三条分支：完整谱形比较；厚度比是否解释剩余差异；离散最高峰是否足以代表谱形相似性。第三条被双方放弃作为充分的比较方法。

这些是实际输出。没有要求当场解决、做实验、写出证明或实现方法，也没有为了凑新颖性改写原候选。

## 完整检查发现的错误

物理研究者选择了两组真实数据：

| 频谱 | 弦长 c | 流速 U | 采样峰频 f | `fc/U` |
|---|---:|---:|---:|---:|
| 50 | 0.0508 m | 39.6 m/s | 3150 Hz | 4.0409 |
| 88 | 0.1016 m | 39.6 m/s | 1600 Hz | 4.1051 |

两个原始峰频相差约 1.97 倍，但无量纲峰位只相差约 1.6%。研究者把前者当成了“`fc/U` 缩放不能使峰位靠近”的反例，混淆了缩放前后的坐标。另一位接受了这个理由，记录员沿用它，错误也进入了概念笔记。

第一次最终检查只收到候选摘要和四份基础摘录，给出 `no_obvious_error`。随后追加的一次检查拿到实际推理与从原始表计算的数值，Luna 明确给出 **`obvious_error`**，同时指出：**撤回这个反例，核心比较问题仍然可以保留。**

原检查未被覆盖：[第一次检查](cases/airfoil_001/run/check_report.json)；[完整证据复核](cases/airfoil_001/reviews/evidence_001/result.json)。两次文献结论均为 `unclear`：四份早期摘要不足以证明新颖性，也不足以完成广泛查重。本次没有让检查 agent 阅读后续文献。

控制器依据完整复核，为本次分支的研究经历和两条相关概念笔记增加纠正版本，旧版本全部保留。纠正明确标为控制器采纳最终检查的结果；没有再调用研究者验证它们是否理解和采用纠正。

## 这次之后具体该补什么

持续记忆本身可直接沿用。当前更需要补两处连接：

1. **个人问题状态和共享问题状态分别保存并传入下一次交流。** 目前双方有独立身份和笔记，但“我原先问什么”的自述仍可能被刚读到的对方问题覆盖。新增的归属审计已暴露这个现象，尚未把语义判断自动化。
2. **最终检查要拿到支持候选的具体证据和推理。** 只看最后一句完整问题，容易漏掉使问题发生变化的错误理由。错误判断应回写为有来源的纠正版本；题目本身是否可继续问，与动机是否算错应分别记录。
