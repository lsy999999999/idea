# 交接与审阅材料精简：实施结果

2026-11-09。已修改实际科研开发工作区、可复用 API 接口，以及尚未启动的历史对照准备目录。研究目标保持为产生新假说，或通过纠正旧假说产生新假说。本次没有启动研究模型。

## 结果提交：保存草稿，只修改局部

首次提交失败后，作者草稿按内容版本保存在本地。接口随后只提供 `patch_result`，例如 `set /summary` 或 `remove /sources/0/extra`。程序在副本上原子应用修改；未涉及的假说、证据和其他字段原样保留，全部校验通过后才提交阶段结果。

下一次请求保留阶段任务与初始材料，但不重复发送此前失败的整份 JSON 和完整工具对话。只补充草稿标识、错误反馈、字段名及新增文档目录。需要了解某个字段时，按文档编号和 JSON pointer 读取。全部原始对话、草稿版本和工具结果仍保存在本地。中断后恢复已准备的提交，不重复应用同一局部修改。

引用别名、原文选择器和空附件的摘要落盘继续由程序处理；程序不猜测或改写科学主张。不完整 JSON 尚不能形成可编辑草稿时，仍需作者提交有效对象。

## 审阅材料：简短目录，原文按需读取

`review-index-v2` 只列阶段、作者、作者摘要短节选、结果与附件引用、此前输入引用。摘要节选明确标注是否完整，仅用于导航。共同资料的路径与版本哈希在统一目录中只登记一次。

API 展示稳定的文档编号与可读取字段，不在首轮自动附上全部研究结果。原文可按段落或分页取回；控制器在本地展开以核验引用。读取目录的子节点时，返回的文档编号仍可直接解析。只有控制器指定的审阅索引可以注册外部文件引用，研究文本不能通过伪造索引获得任意文件访问。

## 离线核验

- 184 项测试通过：API 及索引/局部修复 42，通用科研流程 62，历史流程 80。研究角色为测试样例。
- 检查了局部修改保留其他内容、无效修改原子失败、过期草稿拒绝、中断恢复、原文回查、索引子节点可解析、来源版本变化拦截及历史信息边界。
- 3,900 个既有运行与记忆等受保护文件哈希未变化。
- 开发工作区与准备目录的修改文件已核对；已有冻结运行仍使用归档源码。
