# 假说发展版（2026-11-10）

从已完成的 `hypothesis_continuation_20261109` 当前源码建立的新开发副本。旧运行、研究记忆、终评和原件保持原样；此副本不继承旧候选或研究者记忆。入口是本目录 `runtime/run.py`。

## 已实现的行为

1. **按问题获取本案定义。** 研究者可调用 `request_case_definition(question)`，也可在 `learning_request.case_questions` 中提交问题。隔离的材料读取者查看登记原件，提出有原文依据的中性事实；独立内容检查同时检查问题、拟返回事实和依据。仅放行测量定义、单位、平均/归一化顺序、权重与操作事实；目标解释和结论保持隔离。混合段落可提取其中的中性事实，未记载的内容返回未知。
2. **补学遇到无关结果会重新检索。** 服务按具体请求核对每个来源。标为直接相关/方法相关时必须给出实际原文段落；若都不相关或无法判断，改写检索词后继续检索，最多三次。失败与无关材料均保留，返回明确的未解决状态。这个次数是可继续研究前的一次服务边界，不代表科学能力上限。
3. **后半程进入假说发展回合。** 默认完整上下文路径替换原来的强制记忆示例任务。研究者实际构造、推导、组合、简化、改变假设、调整表征或推导区分后果；允许没有新结果。`development_step.work` 保存实际思考，已有 `hypothesis_updates` 保存假说版本。
4. **同伴比较内容并选择下一步。** 同伴比较控制器指定的两个实际阶段，说明假设、关系、推论发生了什么变化。`next_research_move` 决定接下来继续发展、补学、咨询、暂存或结束；研究者可指定下一位现有参与者。反复澄清/重复的提示来自这些内容比较，作者自报标签另行保存。它不是新颖性或质量评分，也不会自动淘汰假说。
5. **人数与领域可调整。** 默认仍是两位具有领域背景的研究者，允许同一领域不同专长；配置支持一人、两人和多人。研究过程中可提交 `expertise_request:{domain,relation,task,mode:consult/join}`。咨询只参与一次，然后交回请求者；加入者参与后续回合。新研究者读取当前研究问题和任务后入场，不重启整套研究。不会为了保持多样性强制分歧。
6. **记忆服务于研究。** 去掉主流程强制举例展示记忆使用的要求；记忆笔记的 example 字段也已可选。原件索引、唯一标识、允许转述和局部提交修复继续保留。

自查修复后，补学者会重新决定下一步；调度和内容比较使用补学后的实际版本。尚未被研究者阅读的尾部服务回复会交给后续回合，回合用尽则明确记为待处理。服务回复只有通过结构和原文依据检查后才成为可复用结果；无效回复与失败尝试保留，允许修复和恢复。详见 `SELF_REVIEW_CN.md`。

## 配置与启动

使用已有依赖环境；本次没有安装依赖、启动外部模型或进行真实科研试跑。

```bash
/Applications/ideas/research/replication_selection_20261108/execution/.venv/bin/python \
  /Applications/ideas/research/hypothesis_development_20261110/runtime/run.py --case optical
```

默认先完成生成并冻结，再执行独立终评。`--no-evaluate` 仅生成并冻结；`--case wave` 使用另一个已登记案例。终评仍只承担已有研究比较和明显数学/逻辑错误检查。

`model_config.json` 保留本次运行使用的模型/推理设置和原资源配置。新增：

- `hypothesis_rounds: 4`：默认四次研究接续机会，每次由一位研究者推进；可以提前结束。达到边界时记录未完成的下一步，不能解释成科学失败。
- `max_researchers: 6`：此副本的可配置成员上限，包含咨询者。达到上限会保留需求并交回现有团队，不丢弃问题。
- 可选 `researchers: [["researcher_id", "领域/专长"], ...]`：省略时使用案例的默认两人。不会开设一个独立阶段预测总人数。

新启动使用空研究记忆。中断后用同一命令恢复；源码/配置变更后必须使用新的运行副本。已冻结生成不会再调用研究者。旧运行不通过此入口续跑。

## 原件与披露边界

已将现有光学论文缓存、其原始数据 README，以及波动案例论文缓存登记到 `controller_only/<case>/registered_sources.json`。登记内容包括原件和提取文本的哈希；这一步只准备读取条件，没有调用模型生成定义，也没有把原件发给研究者。

原文、服务调用、逐条依据和独立检查保存于控制端。研究者获得单独的事实记录与不透露论文身份的证据 ID，可由控制端审计回原文。定义服务有独立的受限模型通道；普通研究者通道仍执行原论文屏蔽，源文件和私有日志不能经文档工具读取。通用文献的日期和来源规则不放宽。

内容分类由模型判断，精确引文和隔离机制提供可审计约束；离线测试不能证明所有自然语言请求都会被正确分类。原文缺失、判断不确定或出处不匹配时，保留未知/拒绝结果。

## 实现位置

- `runtime/ours_source/src/hypothesis_rounds.py`：实际研究动作、同伴内容比较、后续调度、咨询/加入。
- `runtime/ours_source/src/learning_lab.py`：主流程接线、动态研究身份、记忆、恢复和冻结。
- `runtime/ours_source/src/learning_support.py`：相关性反馈、改变查询、定义请求服务。
- `runtime/definition_service.py`：隔离读取、原文核验、独立内容检查、公开事实与私有依据分离。
- `runtime/run_ours.py`、`runtime/research_tools.py`、`runtime/model_gateway.py`：真实工具/模型通路。
- `runtime/evaluate_frozen.py`：沿用两项独立终评并指向新版运行。

测试与完整性结果见 `IMPLEMENTATION_CN.md` 和 `VALIDATION.json`。实际科研效果需要后续真实运行观察；这里完成的是代码修改和软件验证。
