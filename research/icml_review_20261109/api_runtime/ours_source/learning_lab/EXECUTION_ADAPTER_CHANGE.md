# 执行通道接续记录

首批阶段经已有 Codex CLI 运行器请求 GPT-6 Luna。`04_learn_1` 在已取得 NST 软件手册等资料后遇到 `429 Too Many Requests`，CLI 重试终止；记录保留在原阶段目录。

随后增加 `--executor queue`：控制器保存 `PENDING_NATIVE.json`，包括实际角色任务、输入文件及哈希、指定工作区；主控用原生 collaboration 子代理调用同一指定模型；角色返回后，`import_learning_handoff.py` 校验标准结果字段、实际文件与输入哈希，再保存来源通道、agent 名称、结果哈希和完整派发记录。角色仍按原来的研究流程和长期记忆接口接续。没有把原生调用伪记为 CLI 调用，也没有声称验证后端模型权重。

第二组初始资料由独立原生 Luna 资料角色并行取得，作为 `01_materials` 导入。免疫学研究者的独立阅读可与第一组收尾并行；第二组物理研究者的记忆快照推迟到它实际开始时创建，以取回第一组完成后的知识。

CLI 阶段的工具记录在运行文件中，原生阶段的工具记录在本聊天子代理记录中；本地统一保存派发输入、原始来源与结果。`native_dispatch/` 记录每次原生任务的具体输入和输出来源。
