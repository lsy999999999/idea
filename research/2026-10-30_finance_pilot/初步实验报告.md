# 金融 Agent 方向：第一轮离线实验

日期：2026-10-30。已运行实际公开数据实验，保留输入哈希、逐题输出和可复现程序。

**结论：现在可以低成本启动研究，但本轮没有证明 agent 比普通流程更好。** 历史时点筛选能被简单规则解决；FinQA 的检索确实会漏证据，但提供的上下文很短，必须先比较整页直接阅读。更值得继续调查的是：跨年报发现同一历史指标的变化，找到解释原因的会计附注，并区分正常调整、实质性重述和暂时无法判断的案例。

本轮只运行规则、检索与数据诊断，**没有调用 LLM、训练模型或运行自主 agent**。当前环境没有已配置的模型 API 或本地推理服务。本实验不涉及收费数据库和实地试验。

## 1. 历史财务查询：高平均分掩盖了什么？

**任务。** 指定公司、指标、单位、会计期间和查询截止日期，找出该日期之前最新披露的数值。使用 Apple、Microsoft 的 SEC Company Facts 快照，只保留 10-K/10-K/A、时点数据或 300–400 天的年度期间。

共有 5,912 组跨披露日记录，其中 382 组出现数值变化（Apple 231 组，Microsoft 151 组）。每组取首次披露日、中间披露日和研究截止日，共 **17,736 个查询**；变化组占 1,146 个查询。它们来自两家公司，同组问题相关，不能视为 17,736 个独立公司样本。

参考答案由快照按披露日期回放产生，不是另外人工核验的历史档案真值。查询已经给出精确结构化字段，因此没有测试自然语言理解或指标匹配。

| 方法 | 全部查询：数值正确 | 变化组：数值正确 | 全部查询：数值正确且引用不晚于截止日 |
|---|---:|---:|---:|
| 始终取最早披露 | 96.08% | 39.35% | 96.08% |
| 始终取最新披露 | 97.42% | 60.03% | 50.06% |
| 取出现最多的数值，引用其最新披露 | 97.80% | 65.88% | 50.06% |
| 按截止日期过滤，再取最新披露 | 100.00% | 100.00% | 100.00% |

**解释。** 忽略时间的最新值查询看起来达到 97.42%，但在数值发生变化的子集上只有 60.03%。即使数值相同，引用未来才发布的材料也不能支持“当时已经知道”的回答。这里约一半查询引用未来资料，与我们构造的历史检查点有关，不能推断真实金融工作中一半查询都会犯这个错误。

**具体案例。** Microsoft 的 `AccountsReceivableNetCurrent`，期间截至 2017-06-30：2017-08-02 披露值为 197.92 亿美元，2018-08-03 的记录为 224.31 亿美元。若问题限定在 2017-08-02，直接取最新版本会引入后来的值。这证明记录发生变化，尚未证明变化原因。原始 accession 分别为 `0001564590-17-014900`、`0001564590-18-019062`。

**研究判断。** 日期规则的 100% 是按任务定义实施过滤所得的一致性结果。应把它作为后续系统的基础功能，不能据此声称 agent 创新。快照中的披露日期过滤也不能替代完整的历史数据库版本管理。

## 2. 财务证据检索：问题在哪里，是否需要 agent？

**任务。** 使用 FinQA 全部 883 条开发集问题，对每题随附的文本和表格进行检索，共涉及 299 个不同源页面。答案、计算程序、标注证据和数据集自带检索结果不进入检索语料。比较固定参数 BM25、固定伪相关反馈及随机排序。

指标是“是否取齐所有标注证据”，**不是最终答案正确率**。同一问题可能存在未被标注的替代证据。

| 每题返回片段数 | BM25 取齐标注证据 | 平均返回英文词数 |
|---:|---:|---:|
| 1 | 30.12% | 28 |
| 3 | 54.59% | 83 |
| 5 | 66.25% | 137 |
| 8 | 79.61% | 218 |
| 12 | 87.77% | 321 |

在取 5 段时：

- 只需一条标注证据：384/416，**92.31%**。
- 需要多条标注证据：201/467，**43.04%**。
- 加入一次伪相关反馈：584/883，**66.14%**；原 BM25 为 585/883。10 题改善、11 题变差，862 题不变，没有显示收益。
- 随机排序为 105/883，11.89%，仅作为实现检查用的弱参照。

**抽查发现。** 有些问题缺少比率的分母或期初余额，确实会妨碍计算；有些问题虽然没有取齐标注的说明句，却已经取到了两个所需数字。因此，不能把 33.75% 的标注覆盖失败直接解释成同样比例的回答失败。人工查看的是少量案例，不是全量错误分类。

**关键反证：整页直接阅读很可能足够。** 在第一轮运行后补做的长度诊断显示，完整随附语料平均 742 词、中位数 739 词、95 分位数 1,158 词、最大 1,877 词，所有题均不超过 2,000 个空格分词。这里包含表格的文本序列化，词数不是模型 token 数。返回全部材料可覆盖所有标注证据；尚未测量模型能否据此答对。

这些是数据集提供的页面级上下文，不是完整原始年报。所以本轮只能说明“限制返回片段时，简单检索有瓶颈”，**不能说明 FinQA 必须使用多步 agent**。后续模型对比必须包含整页直接阅读，否则容易人为制造 agent 优势。

## 3. 数值变化是否意味着错误？

结合苹果官方 2020 年四拆一公告，找到 6 组与除以 4 在舍入误差内相符的年度每股指标变化：

| 指标 | 财年 | 较早值 | 较晚值 |
|---|---:|---:|---:|
| 每股股利 | 2018 | 2.72 | 0.68 |
| 每股股利 | 2019 | 3.00 | 0.75 |
| 基本每股收益 | 2018 | 12.01 | 3.00 |
| 基本每股收益 | 2019 | 11.97 | 2.99 |
| 稀释每股收益 | 2018 | 11.91 | 2.98 |
| 稀释每股收益 | 2019 | 11.89 | 2.97 |

单位为美元/股。这些是**与拆股相符的候选案例**，仍需要对应年报附注来确认归因，不能直接作为已人工标注的训练集。公告来源：[Apple reports third quarter results](https://www.apple.com/newsroom/2020/07/apple-reports-third-quarter-results/)。

## 4. 下一步研究选择

建议优先验证这个具体任务：**给定同一历史期间的两个不同财务数值，系统能否找到原始解释证据，说明变化原因、何时开始可知，以及两种数值各适用于什么问题？**

真正需要验证的 agent 行为包括：发现现有材料不足，决定去找哪份年报或附注，核对单位与会计口径，取得证据后更新判断，在证据不足时保留未决状态。它可能帮助金融研究者清洗面板数据、会计研究者整理重述事件，也可能辅助分析师检查跨年口径一致性。现阶段这些是待验证的用途，尚未完成用户访谈或新颖性检验。

下一轮先建立约 30–50 个可复核案例作为流程试验，覆盖正常调整、明确重述和原因未明；这一规模用于发现失败模式，不作为充分发表证据。每例记录两次披露、原始出处、原因说明、时间边界和审核意见。若完整报告和可靠标签拿不到，应先停止扩张数据规模。

有了标签和模型接口后，比较三类流程：①完整相关材料直接输入模型；②固定检索、规则、计算器流程；③允许按缺口追加查证的 agent。共同评估原因判断、引用是否支持结论、历史时点合规、未决案例处理，以及调用成本。测试集应按公司或文档分组，并保留时间边界，不能随机拆同一页面的多个问题。

你能联系的金融或经管老师可具体帮助：确认是否有 Audit Analytics、CSMAR 或相近数据库的相应模块；判断可获取的事件定义及使用许可；核验小批量原因标签和工作需求。数据库权限目前没有确认。**初期需要的是文献、档案和少量专家核验，不需要实地实验。**
