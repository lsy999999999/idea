# 讨论中的按需证据核查 v3

这次修改只接入 `historical_inquiry`。原 `src/learning_memory.py`、原研究者库、旧科学运行与原检查结果保留。通用最终评价器 `src/idea_check.py` 及其 claim-centric-v1 合同未修改。

## 核查何时发生

研究者在普通讨论中可登记一句具体判断、所依据的来源/数据、依赖的先前判断，以及可复查的疑点。没有疑点就返回空数组，不要求每轮提出反驳。

交流、补学、返回讨论及新会话接续结束是批处理节点。具体证据矛盾优先；用来放弃解释、改变问题的事实性前提也可触发，不以双方是否同意为准。探索性猜想不会仅因缺乏证明被送去否决。当前默认每次运行最多 2 批，每批 2 条；超出预算的判断留在 pending 中，不默认为正确。

这是显式登记和路由机制，不是自动识别全部自然语言错误。漏报的重要前提、错误的类型标注和未申报的依赖仍可能漏检。当前只在讨论节点处理，不在一句话中途打断研究者。

## 核查什么、如何回应

内部证据核查者只看目标判断、原始论证、声明的依赖、允许的原始来源与数值。控制器重算采样峰频、`f*c/U`、`f*delta/U`，附单位和采样限制；不运行模型生成的代码。核查者返回有依据的 `supported / needs_correction / undetermined`，纠正必须给出限定范围的替代表述。不评价新颖性或是否准许保留一个 idea。

核查报告交回共同讨论，两位研究者均可接受、有依据地反驳、或保留未决，并明确错误依据与问题本身各受什么影响。第二位能看到第一位的实际回应。依赖该判断的记录标为需要重新考虑，不会自动全判为错误，也不会自动覆盖个人或共享问题。

每位研究者把实际回应保存为有报告来源的纠正/争议笔记。已识别的受影响笔记必须在原 key 下新增版本；旧版、错误解释与分支保留。后续修订必须保留已有内部报告的来源。笔记正文是否充分吸收纠正仍需审读，来源校验不能替代科学判断。

## 最终评价边界

研究接续先完成，候选和全部讨论证据再冻结。最终检查只能读冻结输出；其结果不写进研究记忆，不触发当前运行的再生成。入口取消自动运行会写入纠正记忆的旧 `review.py`，保留该文件及旧结果。

最终历史检查收到完整生成讨论和实际数据；因只有 4 份许可摘要，新颖性可能只能是 `unclear`。未来跨系统评价仍应统一使用项目通用评价器；本次没有开展比较或改造那个评价器。

## 验证

运行软件回归：

```bash
.venv/bin/python -m unittest discover -s historical_inquiry -p 'test_*.py'
.venv/bin/python -m unittest discover -s tests -p 'test_learning*.py'
```

覆盖：猜想不被拦截、共识事实前提仍可核查、依赖传播、预算和剩余项、精确证据引用、坐标复算、两位研究者回应及记忆版本、最终评价隔离、初始独立性、恢复时不混入未来依赖。

`replay_correction.py` 另建情境，在初始状态植入已知坐标错误和一条尚未证实的猜想，然后调用 Luna 核查、两位研究者讨论及记忆接续。它验证纠错链路，不证明系统能自发发现任意错误。原论文正文与截止日之后的工作不提供给任何回放角色；预训练知识无法据此排除。

```bash
.venv/bin/python -u historical_inquiry/replay_correction.py --case coordinate_replay_001
```

已冻结运行的精确输入不得替换。若改变提示、供给证据或协议，请用新的情境或 run-id。模型原始回答、失败尝试、修复及执行审计全部保留。回放结果另存，不改写原 `RESULTS_CN.md` 或 `FINAL_STATUS.json`。
