# 个人问题归属与共享问题状态修复

2026-11-05，按用户要求修改新增试跑入口；原持续记忆实现不变。

## 具体改动

旧接口让 agent 从混合上下文生成 `question_before`，没有定义它指个人问题还是共同讨论的问题。新接口由代码提供三组带 ID、归属、版本和出处的记录：自己的当前问题、各位同行的个人问题、当前共享问题。

agent 分别对个人问题和共享问题作决定，不再生成“此前问题”的自由文本。修改前记录直接取自存储。保留问题必须保持文本不变；修订需要原因和正确的基础版本。可以主动采用对方的研究方向，这会成为本人问题的新版本，旧问题和转向理由保留。

共享问题的变化不会自动改动任何个人问题，也不代表全体同意。代码只核对归属和版本，不判断问题是否新颖或改变是否有科学意义。

## 文件与运行边界

- `question_state.py`：个人/共享问题的状态、不可变事件及实际输入快照。
- `run.py`：在交流、补学、返回和新会话中传入明确状态；在写入笔记前检查更新；记录员接收真实问题轨迹。
- `review.py`：仅调整新运行的输出路径和记忆来源任务，继续保留原来的两项检查。
- `test_question_state.py`：10 项状态和控制器回归测试；模型调用为 mock。

新运行默认使用 `cases/airfoil_001/runs/questions_v2/`。原 `run/`、`reviews/`、原始角色回答及原代码快照不迁移、不回填。长期知识依然使用现有 `Memory` 类，提交来源带上具体运行 ID，避免不同运行相互覆盖提交记录。
