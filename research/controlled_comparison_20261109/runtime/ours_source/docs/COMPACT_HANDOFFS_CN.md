# 简短交接与按需回查

新通用运行使用 `learning-inquiry-v5-compact-review`；API 使用 `tool-transport-v7-delta-review`。研究目标仍是产生新假说，或通过纠正旧假说产生新假说。

提交结果若未通过校验，API 在本地保存作者的原始草稿和版本。随后提供 `patch_result`，只提交需要改变的字段（JSON pointer、set/remove、值）。程序在草稿副本上原子应用修改，未涉及的字段原样保留；通过全部既有校验后才提交研究状态。旧草稿、工具调用和完整会话仍存档。修复请求只携带当前草稿标识、错误提示和新增文档目录，不重复发送此前失败的完整结果；必要时用 `read_document` 读取草稿某个字段。中断恢复复用已准备的草稿，防止重复应用同一修改。

审阅材料使用 `review-index-v2`：每个阶段只列作者、作者摘要的短节选、结果/附件引用和此前输入的引用。节选是导航，不是完整证据。文件路径、内容哈希和版本只在统一目录登记一次，不再将各阶段全文及其嵌套输入反复嵌入审阅包。

API 把目录转换为阶段内可读的 D 文档标识；文件执行器可通过索引登记路径读取。需要具体论据时，按文档标识和 JSON pointer/分页读取原文。程序在本地展开并核验引用，不把展开内容重新送给模型。旧版内嵌材料仍可被本地审计器读取；原文变动、过期草稿引用和无效局部修改会被拒绝。

这次改变的是材料组织和接口恢复，不改变研究角色、假说保留规则、终评范围或历史信息限制。没有增加研究模型调用阶段。必须使用新的运行目录；不以新代码续跑冻结实验。

验证与离线输入量测量见 `/Applications/ideas/research/compact_handoffs_20261109/`。首轮输入减少不等于整个科研任务等比例降费；后续读取和实际研究质量仍需另行观察。
