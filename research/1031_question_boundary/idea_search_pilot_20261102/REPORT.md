# 连续探索试验：简单历史提示已能扩展方向，复杂机制未获得额外收益

2026-11-02。两个新公开数据场景，三种策略，每种连续三轮。54次科学生成、54条初始候选、18条最终记录全部保留；另有2次隐藏策略名称的模型评审。使用请求模型 gpt-6-luna。

**本轮决策：不扩大复杂机制C。简单历史提示B得到6个可验收的不同最终方向，C得到5个；C还发生了一处生成者、负责人和另一个上下文的模型评审均未发现的科学验收错误。** 这是一轮开发性试验，每任务每策略只有一条序列，不是统计优劣或原创性结论。

## 做了什么

数据为食品品质场景 UCI 186 Wine Quality（6,497行）和电商行为场景 UCI 468 Online Shoppers Purchasing Intention（12,330行），均不同于此前六领域试验的数据集，仍是熟悉的历史公开数据。每轮负责人提出三候选，执行者批评并最多请求一次计算和一次Crossref检索，负责人依据真实返回作最终判断。每条序列可见自己的完整历史，不共享其他组输出。

|策略|内容|
|---|---|
|A：有历史的现有流程|保留三阶段角色流程及完整历史，不另加避免重复要求|
|B：简单历史提示|A加上“避免重复历史核心方向；同族推进须增加可区分预测”|
|C：结构化比较与选择规则|B加上结构对照、失败类型分类；按模型自报质量门槛、历史关系、现有数据可检验性固定排序|

三组使用相同角色原则、方法索引、记录字段、调用与工具额度。A也有共同结构字段，因此是增强后的有历史基线，并非原来全新上下文的精确复刻。C是提示与选择规则的组合原型，本轮不能归因到其中某一个组件。未证明该设计在文献上新颖。

事前决定：只有C在两个任务上都比B至少多一个可验收的最终思路族，且没有更多实质验收错误，才扩大C。见[冻结协议](PROTOCOL.md)、[冻结清单](FROZEN_DESIGN.json)、[去留判定](GO_NO_GO.json)。

## 主要结果

“可验收”要求问题具体可检验、测量和逻辑一致、计划可行，并且最终证据解释没有实质错误。未计算但清楚标为提案的候选可以通过；blocked/withdrawn记录不计成交付的最终候选。思路族按核心问题去重，不等于文献原创性。

|策略|葡萄酒：可验收最终候选 / 去重方向|购物：可验收最终候选 / 去重方向|合计去重方向|确认的实质验收错误|
|---|---:|---:|---:|---:|
|A|0 / 0|3 / 2|2|0|
|B|3 / 3|3 / 3|6|0|
|C|2 / 2|3 / 3|5|1|

累计可验收方向曲线（第1、2、3轮）：葡萄酒A为[0,0,0]、B为[1,2,3]、C为[1,1,2]；购物A为[1,1,2]、B和C均为[1,2,3]。

A的葡萄酒“0”不意味着没有研究问题：第1和3轮保留了具体问题，但明确标为blocked；第2轮最终把主要预测收窄成嵌套模型的样本内拟合改善，隐藏组名评审认为该字面预测不足以区分假说。它确实给出了非平凡的名义似然比统计量，因而存在评分边界：若把这一条件拟合比较作为可用提案，A葡萄酒可记1个方向。此敏感性不改变C未超过B的结论。

隐藏组名模型评审最初判B和C均为6个方向、均无实质错误。组织者随后发现C葡萄酒第2轮抽取了错误的回归系数，将该轮从可验收列表排除，保留其问题本身。模型评审原文没有改写，修改理由另存[组织者审查](ORGANIZER_AUDIT.json)。最终机器可读汇总见[FINAL_SUMMARY.json](FINAL_SUMMARY.json)。

## 最重要的发现：正确运行和另一次模型评审都没有保证科学验收

C葡萄酒第2轮的问题是“柠檬酸是否调节挥发酸与质量评分的关联”。其序数回归设计矩阵的前四列为：

1. volatile_acidity；
2. citric_acid；
3. volatile_acidity × citric_acid；
4. fixed_acidity。

Python从零编号，交互项对应`beta[2]`，代码却返回`beta[3]`。因此原报告中的点估计和80次bootstrap区间全部属于固定酸度主效应，却被命名为交互效应。

|颜色|原来误标为交互的数值及95%区间|仅修正取值位置后的真正交互及95%区间|
|---|---|---|
|红葡萄酒|0.2663，[-0.0241, 0.5686]|0.1082，[-0.0740, 0.2296]|
|白葡萄酒|0.1941，[0.0547, 0.3079]|0.0275，[-0.0231, 0.0665]|

拟合方程、输入行、标准化、随机种子、bootstrap样本和优化设置均未改变，只修正返回系数的位置。原来对白葡萄酒“交互方向获得支持”的依据因此被推翻；修正结果是不确定，不能解释成证明交互不存在。

执行者没有发现这一索引错误，负责人依据它保留了观测支持；隐藏策略名称的另一次模型评审也接受了该结果。原科学代码可以逐字节复现错误输出。这个案例与此前能源时间单位错误共同说明，**研究验收需要检查科学量与实现输出之间的对应关系**。这是一项得到具体案例支持的问题线索，尚不是经过专项查新的独有方法贡献。

诊断只在生成与模型评审完成后运行，没有回灌角色，也不算agent自发修复。见[诊断设计](organizer_diagnostics/wine_C_r2_coefficient/DIAGNOSTIC_DESIGN.json)、[修正结果](organizer_diagnostics/wine_C_r2_coefficient/RESULT.json)。

## 搜索行为与另外两项检查

18轮初选有16轮选择I1。C在购物第2、3轮主动选择I3。固定排序规则18次都与模型初选一致，未单独产生一次改选；这不证明规则的提示完全无影响，但不能把I3转选归因于外部排序纠正了模型。

简单提示B确实生成了与历史不同的问题。例如葡萄酒依次涉及酒精×糖交互、化学近邻的评分一致性、不同评分阈值的关联；购物依次涉及浏览时长分配、SpecialDay相对月份的增量、浏览深度差异的组成分解。这些是研究候选，尚未确认世界文献原创性。

C葡萄酒第1轮的正文明确说区间跨零、方向未获支持，但证据枚举仍填`observational_support`。本报告将其保留为有用的待检验提案，并单独记标签不一致；若严格排除该标签冲突，C葡萄酒会由2个降为1个，去留结论不变。

C购物第3轮把相同的product-share值按原行顺序拆成等人数十分位组：4,760条记录的share恰好为1，最高四组的share完全相同，转化率却从4.91%到14.81%不等。这些组间起伏不是share变化的响应。按相同数值不拆分重分箱后，整体边际图样仍非单调，因此该诊断不推翻继续检验非线性的提案；它指出了不能信任原细分组曲线的原因。见[同值分箱诊断](organizer_diagnostics/shopping_C_r3_ties.json)。

## 执行、成本与证据边界

- 54次生成阶段全部完成，没有为了更好的科学答案重新生成。另有2次评审调用和1次成功的非科学连通性测试。
- 18次计算请求：12次执行成功、3次运行失败、3次被语法/接口检查拒绝。12个成功脚本的冻结后复跑输出全部逐字节一致；这验证复现性，不保证科学含义正确。
- 13次文献请求：9次返回、4次连接失败。返回内容主要为Crossref元数据，不能裁定原创性。
- 全部旧12轮的封存文件仍与原哈希一致；恢复分支643个封存文件通过核对。见[完整性审计](format_recovery/INTEGRITY_AUDIT.json)和[数值复跑](format_recovery/NUMERICAL_REPLAY.json)。

本轮存在明确的接口修复：原严格JSON协议下六条序列均因某次回答末尾多一个`}`而停止，合计完成7轮。原始结果仍在`runs/`。全部停止后建立`format_recovery/`副本，采用事先写入修复协议的唯一规则：读取完整字典对象，只允许剩余内容恰为单个`}`。全程8个回答采用该规则，没有改动任何科学字段或增加科学阶段调用；之后完成原定剩余轮次。见[格式恢复协议](FORMAT_RECOVERY_PROTOCOL.md)。因此最终表属于透明记录的技术修复分支，不能声称整个执行过程从未改动过。

准备阶段购物CSV下载曾超时；初次准备错误地接受了可解析的部分文件。此问题在任何科学生成前发现，旧准备清单作废并保留，重新下载和校验完整12,330行后才开始。葡萄酒官方元数据的4,898对应白葡萄酒数量，联合CSV实际为4,898白+1,599红，实际数量及原元数据一并提供。

每格只有一条三轮序列，没有独立重复；第一轮生成也没有共同前缀，初选差异和随机性可能影响后续。评审使用同一模型的独立上下文，组名与含组名的错误路径被隐藏；它不是领域专家盲评。组织者知道设计。初始思路族的精细度也有主观性，例如颜色差异与标准化颜色差异是否归为一族。主结论是本轮没有达到扩跑门槛，不是B的统计优势、C普遍无效或长期创造能力的判断。

## 下一步判断

1. **不扩大C当前组合。** B已达到每任务三轮三个可验收方向，C没有增加产出且漏验一个错误系数。继续堆结构字段或更多角色缺少本轮证据支持。
2. **保留B作为后续的廉价强基线。** 下一轮若研究持续探索，应增加独立任务、序列长度和重复，并检查B何时开始重复；不能从三轮就推断持续性问题已解决。
3. **优先验证“科学量—实现—结论”的验收问题。** 将本轮错系数、此前时间单位错误作为开发用例；对现有代码审查、显式变量名绑定、独立数值校验、已有反证式agent进行同预算比较。最终测试必须包含未见过的自然错误与正常代码，衡量漏检、误拒和成本。先查最近工作和强基线，再决定能否形成顶会方法贡献。
