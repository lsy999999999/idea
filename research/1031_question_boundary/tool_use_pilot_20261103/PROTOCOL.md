# 工具使用开发试验：预先冻结方案

本轮解决一个具体问题：agent 能否把新量或关系落实成可执行模型，并利用工具反馈修订，而不再停在单位、系数和表达式错误上。它是同一已反复开发的模拟机制上的工具可行性试验，不是开放发现评测，也不检验世界原创性。

## 三个条件

- direct：gpt-6-luna / low 连续4次提交完整公式；每次收到同一编译器和数值拟合反馈。单位由工具推断。每个公式最多8个共享参数、1600次实际残差计算。
- agent_tools：同一模型连续4次自主选择 representation_check 或 complete_model。前者检查给下游函数的实际特征是否合并了已有证据要求区分的情形；后者在 agent 自己选择的量、特征和多项式次数中完成系数/交互项搜索。每次最多1600次实际残差计算、每条件总计6400次；最多8个最终共享参数，其中最多2个非线性参数。检查也占用一次模型决策。
- tool_only：没有LLM。对预先声明的原始输入通用浅语法目录自动搜索，依次采用完整目录、去除三角函数目录、去除双曲函数目录、仅保留多项式目录；4次调用，每次1600次、总计6400次残差计算。目录是在已知开发机制上设计，故其成功只能证明目录覆盖与求解可行。

工具是本地实际执行的受约束数学程序。LLM 通过结构化 JSON 选择工具和参数，由 runner 执行后把原始结果返回下一轮；不是任意代码执行或原生 API function-call 性能试验。各条件不能看到其他条件的候选、反馈或结果。

## 共同信息、选择和验收

共用前轮冻结的 fit/dev 原始数据、已有观测前提与相同数学运算语言，不提供旧候选公式、模拟器源码、隐藏目标或真实系数。复用同一开发机制的历史对方法设计已有影响，必须在报告中说明。

参数仅在 fit 上估计，结构和最终模型按 dev RMSE 选择。不得用 dev 优化参数向量。4次决策后每条件冻结一个收敛且编译有效的最佳 dev 模型，即便其未达标，也记录独立结果，不能事后更换。研究推断调用最多8次，仅允许失败传输原输入重试一次；禁止自主文件、网络、shell 或委派调用。

冻结代码、数据、条件和选择规则后再研究推断；全部条件选择冻结后才读取新隐藏目标或获取确认观测。所有条件使用共同的200条随机隐藏记录、16个随机条件各4次确认观测，以及 direct/agent_tools 最终选择候选提出的最多4个条件的并集（各4次）。预测和参数先冻结再获取确认结果。验收需收敛、dev/hidden/随机确认 RMSE 均不超过0.06；若存在合法的agent提出确认条件，其并集 RMSE 也须不超过0.06。不能把同一隐藏集反馈用于下一轮修改。

保存每次原始输出、无效工具请求、全部搜索轨迹、自动完成公式、参数绑定、预测与时间/用量。数值资源上限相同不代表等计算；报告实际残差次数、线性求解次数、推断用量与语法差异。单次链条不能确立方法平均收益。

## 预设解释

- 只有工具层跑通：工程可行，不算科学预测成功。
- 通过独立预测：该开发例子上可预测，尚不唯一确定潜在机制。
- tool_only 同样通过：不能把成功归于LLM科学推理；检查LLM是否节省搜索或提出目录之外的有效结构，作为待检验假说。
- 全部失败：根据原始轨迹区分表示丢失、结构表达不足、估计失败和选择失败，停止扩展运行数量。
- 下一阶段需要冻结方法后换未用于设计的新机制与组合；检索、跨域迁移、可执行新测量仍未在本轮接入。
